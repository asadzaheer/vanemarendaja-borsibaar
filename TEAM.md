## Team Workflow
- We use the forked team repository as our shared workspace.
- Only one initial commit is pushed directly to `main` (this file).
- All further changes are done in feature branches (e.g., `feature/<topic>`).
- Each feature requires multiple commits and is merged via Pull Requests.
- Every Pull Request must have at least one peer review (comments + approval).
- We will demonstrate at least two merge strategies (merge commit and squash/rebase).
- We will intentionally create and resolve one merge conflict locally using the command line.
