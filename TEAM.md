## Team Workflow
- We use the forked team repository as our shared workspace.
- The main branch is protected, so all changes are made through feature branches and Pull Requests.
- Each developer works on their own feature branch (e.g., `feature/<topic>`).
- Every feature includes multiple commits and is merged via Pull Requests.
- Each Pull Request must have at least one peer review (comments + approval).
- We will demonstrate at least two merge strategies (e.g., merge commit and squash/rebase).
- We will intentionally create and resolve one merge conflict locally using the command line.
